# Reference Sheet 04: SQL

SQL = Structured Query Language. Examples use this project's tables: `users`, `categories`, `products`, `stock_movements`.
Run them in PostgreSQL (`psql`) or in any SQL client.

## Reading data

```sql
SELECT sku, name, price FROM products WHERE price > 10 ORDER BY price DESC LIMIT 5 OFFSET 0;   -- paging
SELECT DISTINCT category_id FROM products;
SELECT * FROM products WHERE name ILIKE '%cable%';                -- ILIKE = case-insensitive (PostgreSQL)
SELECT * FROM products WHERE quantity BETWEEN 1 AND 10 AND category_id IN (1, 2);
SELECT * FROM products WHERE description IS NULL;                 -- never "= NULL"
```

## Joins

```sql
-- INNER JOIN: only rows that match on both sides
SELECT p.sku, p.name, c.name AS category
FROM products p
JOIN categories c ON c.id = p.category_id;

-- LEFT JOIN: keep every category, even those with no products
SELECT c.name, COUNT(p.id) AS products
FROM categories c
LEFT JOIN products p ON p.category_id = c.id
GROUP BY c.name;
```

## Aggregates

```sql
SELECT category_id, COUNT(*) AS n, SUM(quantity) AS units, AVG(price) AS avg_price, MAX(price) AS top
FROM products
GROUP BY category_id
HAVING SUM(quantity) > 0;          -- HAVING filters groups; WHERE filters rows before grouping

-- stock value per category
SELECT c.name, SUM(p.price * p.quantity) AS stock_value
FROM products p JOIN categories c ON c.id = p.category_id
GROUP BY c.name ORDER BY stock_value DESC;
```

## The low-stock report (same as `findLowStock`)

```sql
SELECT * FROM products WHERE quantity <= reorder_level ORDER BY quantity, name;
```

## Subqueries, CTEs, window functions

```sql
-- products never moved
SELECT * FROM products p WHERE NOT EXISTS (SELECT 1 FROM stock_movements m WHERE m.product_id = p.id);

-- CTE (Common Table Expression): a named temporary result
WITH sold AS (
  SELECT product_id, SUM(quantity) AS units_out
  FROM stock_movements WHERE movement_type = 'OUT' GROUP BY product_id
)
SELECT p.name, s.units_out FROM sold s JOIN products p ON p.id = s.product_id ORDER BY s.units_out DESC;

-- window function: running stock level per product
SELECT product_id, created_at, resulting_quantity,
       ROW_NUMBER() OVER (PARTITION BY product_id ORDER BY created_at DESC) AS recency
FROM stock_movements;
```

## Changing data

```sql
INSERT INTO categories (name, description) VALUES ('Toys', 'Games and toys');
UPDATE products SET price = price * 1.05 WHERE category_id = 1;     -- ALWAYS check the WHERE first!
DELETE FROM stock_movements WHERE created_at < now() - INTERVAL '2 years';
```
Tip: run the matching `SELECT` first to see which rows you are about to change.

## Defining structure (see `V1__create_schema.sql`)

| Concept | Example |
|---|---|
| Primary key | `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| Foreign key | `category_id BIGINT NOT NULL REFERENCES categories (id)` |
| Unique | `sku VARCHAR(40) NOT NULL UNIQUE` |
| Check | `CHECK (quantity >= 0)` |
| Default | `DEFAULT CURRENT_TIMESTAMP` |
| Index | `CREATE INDEX idx_products_category ON products (category_id);` |
| Change a table | `ALTER TABLE products ADD COLUMN barcode VARCHAR(30);` (in a NEW Flyway file, e.g. `V3__add_barcode.sql`) |

Data types: `INTEGER`, `BIGINT`, `NUMERIC(12,2)` (exact money), `VARCHAR(n)`, `TEXT`, `BOOLEAN`, `DATE`, `TIMESTAMP WITH TIME ZONE`.

## Transactions

```sql
BEGIN;
UPDATE products SET quantity = quantity - 3 WHERE id = 5 AND quantity >= 3;
INSERT INTO stock_movements (product_id, movement_type, quantity, created_by, resulting_quantity)
VALUES (5, 'OUT', 3, 'admin', 7);
COMMIT;      -- or ROLLBACK; to undo everything since BEGIN
```
ACID = Atomic (all or nothing), Consistent (rules hold), Isolated (transactions do not see each other half-done), Durable (committed data survives a crash).

`SELECT ... FOR UPDATE` locks the selected rows until the transaction ends. This is what `findWithLockById` does.

## Performance basics

* Index columns you filter or join on (`WHERE`, `JOIN ... ON`). Primary keys and `UNIQUE` columns are indexed automatically.
* `EXPLAIN ANALYZE SELECT ...` shows how the database ran the query: look for "Seq Scan" on big tables.
* `SELECT *` pulls every column; list only what you need.
* A leading wildcard (`LIKE '%abc'`) cannot use a normal index.

## `psql` commands (PostgreSQL console)

`\l` list databases, `\c inventory` connect, `\dt` list tables, `\d products` describe a table, `\q` quit.
